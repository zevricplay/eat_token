# Contributing Guidelines

Thank you for considering contributing to the Free Fire Token Generator project! 🎉

## 🤝 How to Contribute

### 1. Fork the Repository
```bash
git clone https://github.com/zevricplay/eat_token.git
cd eat_token
```

### 2. Create a Feature Branch
```bash
git checkout -b feature/your-feature-name
```

### 3. Make Your Changes
- Write clear, descriptive commit messages
- Follow the existing code style
- Test your changes thoroughly

### 4. Commit Your Changes
```bash
git commit -m "Add: Description of your feature"
```

### 5. Push to GitHub
```bash
git push origin feature/your-feature-name
```

### 6. Open a Pull Request
- Describe what your PR does
- Link any related issues
- Include screenshots if applicable

## 📝 Commit Message Format

```
type: subject

body

footer
```

### Types
- `feat:` A new feature
- `fix:` A bug fix
- `docs:` Documentation changes
- `style:` Code style changes (formatting, etc)
- `refactor:` Code refactoring
- `perf:` Performance improvements
- `test:` Adding or updating tests
- `chore:` Build process, dependencies, etc

## 🐛 Bug Reports

Please use the GitHub Issues tab to report bugs. Include:
- Clear description of the bug
- Steps to reproduce
- Expected behavior
- Actual behavior
- Browser/OS information
- Screenshots if applicable

## 💡 Feature Requests

Have an idea? Open an issue with:
- Clear description of the feature
- Use cases
- Possible implementation approach
- Any related issues/PRs

## 🎨 Code Style

### HTML
- Use semantic HTML5 elements
- Indent with 4 spaces
- Meaningful class names

### CSS
- Use CSS variables for colors
- Follow BEM naming convention
- Mobile-first approach
- Group related properties

### JavaScript
- Use ES6+ features
- camelCase for variables/functions
- Meaningful variable names
- Add comments for complex logic
- Use arrow functions where appropriate

## ✅ Testing

- Test your changes in multiple browsers
- Test on mobile devices
- Verify localStorage functionality
- Check clipboard operations
- Test error handling

## 📚 Documentation

- Update README.md if adding features
- Document API endpoints
- Add inline comments for complex code
- Include usage examples

## 🚀 Pull Request Process

1. Update README.md with any new features
2. Update CHANGELOG.md with your changes
3. Ensure all tests pass
4. Provide detailed PR description
5. Link related issues

## 📋 Code Review

All PRs will be reviewed by maintainers. We may:
- Request changes
- Ask clarifying questions
- Suggest improvements
- Request documentation updates

## 🏆 Recognition

Contributors will be:
- Listed in CONTRIBUTORS.md
- Mentioned in release notes
- Added to README.md

## 📞 Questions?

- Open an issue with `[question]` tag
- Contact: support@fftools.site

---

**Thank you for contributing! 🙏**
